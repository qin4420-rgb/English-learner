# English Room「资源整理」需求说明（PDF 与视频）

版本：需求草案 v1.0  
用途：作为 English Room 第二版开发、验收和后续调整的依据。

## 1. 目标

在现有“课程、资源库、进度、维护中心”之外增加独立的“资源整理”板块，把分散的 PDF、文章、视频链接和字幕整理为可搜索、可阅读、可复习的私人资料库。

核心目标：

1. 原始资料只作为输入，最终重点保存体积更小、结构更清楚的正文、字幕和元数据。
2. 自动识别标题、文章边界、主题、摘要和关键词，但所有自动结果都可人工修改。
3. 整理结果经过确认后再进入正式资源库，不把 AI 结果直接当作最终资料。
4. 保留来源、页码、时间点和处理版本，后续能够追溯原文。
5. 支持批量处理和自动化，但自动导入来源必须经过白名单与授权检查。

## 2. 新增板块与页面

### 2.1 资源整理工作台

显示以下状态：

- 待处理
- 正在提取
- AI 整理中
- 待人工审核
- 已归档
- 处理失败

支持按资料类型、刊物、日期、主题和状态筛选，并显示本月处理量、文章数量、文本体积、节省的原文件空间和 API 使用量。

### 2.2 PDF 整理

上传数字版 PDF，填写或自动识别刊物名称、期号/日期和来源。系统提取正文、识别文章候选并生成归档信息。

### 2.3 视频整理

录入视频链接或上传字幕文件，保存视频元数据、字幕、章节、摘要、主题和学习笔记。第一阶段以“链接 + 字幕/文本”为主，不长期保存大型视频文件。

### 2.4 审核窗口

在归档前检查自动结果，支持：

- 修改标题、日期、主题、摘要和关键词
- 合并被错误拆开的文章
- 拆分被错误合并的文章
- 删除广告、目录页、版权页和无关页面
- 对照原 PDF 页码或视频时间点
- 选择“确认归档”或“退回重新处理”

### 2.5 清洁阅读页

归档后的文章提供适合电脑、平板和手机的阅读页面，包含：

- 英文正文与清晰段落
- 中文内容摘要
- 主题、关键词、刊物、日期和文章序号
- 原始页码或视频时间点
- 阅读进度、收藏和个人笔记
- 返回期刊目录和资源库的入口

## 3. PDF 处理需求

### 3.1 输入

- 首期支持带文字层的 PDF。
- 扫描版 PDF 标记为“需要 OCR”，放到后续阶段处理。
- 支持单文件上传和批量上传。
- 上传时可选择是否保留原 PDF。
- 大文件可在本机提取文字后只上传结果，降低网站存储压力。

### 3.2 刊物级信息

每份 PDF 建立一个“期刊/资料包”父档案：

- 刊物名称，例如 The Economist
- 期号或出版日期
- 年、月、周次
- 原始文件名
- 文件大小、页数和文件指纹
- 来源说明与来源链接
- 获取日期
- 是否保留原文件
- 处理状态与处理版本

文件指纹用于避免同一 PDF 被重复整理。

### 3.3 文章识别与清洗

系统尝试利用目录、标题样式、栏目名、页码和页面连续性识别文章边界，同时完成：

- 删除重复页眉、页脚和页码
- 修复 PDF 换行、断词和多栏阅读顺序
- 过滤广告、图片说明、目录页和版权页
- 保留标题、副标题、小标题和段落结构
- 记录文章对应的原始页码范围

自动识别不可靠时必须进入人工审核，不能直接覆盖已确认内容。

### 3.4 文章级信息

每篇文章至少保存：

- 文章唯一编号
- 所属刊物与期号
- 本期第几篇
- 英文原标题
- 可选中文标题
- 栏目/版块
- 作者（可识别时）
- 原始页码范围
- 英文词数和预计阅读时间
- 主主题与次主题
- 关键词
- 中文主要内容摘要
- 可选英文短摘要
- 清洗后的英文全文
- 来源、处理时间、AI 模型和提示词版本
- 审核状态、确认时间和修改记录

### 3.5 进入资源库后的结构

资源库采用两层结构：

```text
The Economist
└── 2026-08-08 期
    ├── 第 01 篇｜文章标题
    ├── 第 02 篇｜文章标题
    └── 第 03 篇｜文章标题
```

资源库可按刊物、日期、主题、关键词、阅读状态和难度筛选，并支持全文搜索。

## 4. 视频整理需求

### 4.1 输入方式

- 视频网页链接
- 网盘链接
- 自有视频文件
- SRT、VTT 或纯文本字幕
- 手工粘贴的字幕或学习笔记

第一阶段优先保存链接和字幕，不复制或长期存放外部平台的视频文件。

### 4.2 视频级信息

- 标题
- 来源平台与频道/作者
- 原始链接
- 发布日期
- 时长
- 语言与字幕情况
- 主题、关键词和难度
- 中文摘要
- 观看进度与收藏状态

### 4.3 字幕与章节整理

有字幕时，系统按时间段整理：

- 清洗字幕中的重复和无意义文本
- 按话题变化生成章节
- 每章保存开始/结束时间、标题和摘要
- 生成整段视频摘要、主题和关键词
- 保留时间点，点击章节可回到对应视频位置
- 可选提取重点表达、生词和例句

没有字幕时，先进入“需要转写”状态。视频语音转文字需要独立的语音识别能力，不能只依赖 DeepSeek 文本接口。

## 5. AI 与 API 方案

### 5.1 DeepSeek API

DeepSeek API 作为网站自动整理的首选文本模型：

- 判断文章边界和栏目
- 生成结构化标题、摘要、主题和关键词
- 输出固定 JSON，便于程序校验和入库
- 对长文章分段处理，再生成全局摘要
- 对不确定结果给出置信度和“需要人工审核”标记

模型名称、价格和上下文能力会变化，因此放在维护配置中，不写死在业务代码里。默认优先选择成本较低的非深度思考模型；只有边界识别困难或结果不合格时才升级到更强模型。

DeepSeek 密钥只保存在网站服务器的加密环境变量中，不写入网页、GitHub、浏览器缓存或导出备份。

### 5.2 ChatGPT 会员与 Codex

ChatGPT 会员主要用于：

- 在 Codex 桌面客户端协助开发和调整网站
- 对少量疑难文章进行人工式复核
- 修改提示词、分类标准和页面功能
- 批量处理失败时进行一次性修复

ChatGPT 会员不能直接当作网站后台的 OpenAI API 额度。ChatGPT 与 OpenAI API 是分别管理和计费的产品；如果未来需要 OpenAI API 作为备用模型，需要单独配置 API 账户和费用上限。

### 5.3 成本控制

- 上传前估算页数、字数和预计调用量
- 显示“预计成本”，由用户确认后开始 AI 整理
- 设置单文件、每日和每月调用上限
- 优先使用缓存和相同提示词前缀
- 失败重试设次数上限，避免无限扣费
- 保存每次任务的输入/输出 token 与费用记录
- 支持“只提取文字，不调用 AI”模式

## 6. 自动化流程

完整流程：

```text
资料进入
→ 文件/链接去重
→ 文字或字幕提取
→ 结构清洗
→ 文章/章节识别
→ DeepSeek 生成结构化信息
→ 程序格式校验
→ 人工审核
→ 归档到资源库
→ 阅读进度与笔记
```

自动化来源可以包括：

- 指定本地/网盘上传入口
- 有授权的 RSS、公开 API 或下载源
- 经过确认的 GitHub 仓库发布记录
- 手工粘贴的视频或文章链接

GitHub 项目“可以公开访问”不等于内容“可以自由复制”。自动化前必须记录仓库许可证、内容来源和允许的使用方式。未确认授权的来源只能建立链接或待处理记录，不能自动复制全文。

## 7. 存储方案

### 7.1 建议保存

- 结构化元数据：数据库
- 清洗后的正文、字幕和 Markdown：对象存储
- 小型 PDF、字幕和附件：私人文件区
- 大型原始 PDF/视频：Google Drive、百度网盘或对象存储
- 网站代码和配置：GitHub

### 7.2 原文件处理默认规则

- PDF：默认保留至用户确认归档；确认后可自动删除原 PDF，只保留文字、元数据和来源指纹。
- 视频：默认不复制外部视频，只保存链接、字幕、摘要和笔记。
- 重要原件：可选择长期保留，或备份到 Google Drive/百度网盘。
- 删除原件前显示明确提示，并保留可导出的整理结果。

## 8. 搜索与分类

统一搜索范围：

- 文章/视频标题
- 刊物、期号和栏目
- 主题与关键词
- 摘要
- 正文与字幕
- 个人笔记

第一版主题分类建议：

- 经济与金融
- 商业与管理
- 政治与国际
- 科技与人工智能
- 科学、健康与环境
- 文化、历史与社会
- 教育与语言学习
- 其它

允许一项资料包含一个主主题和多个次主题，避免只能放在一个文件夹的问题。

## 9. 安全、隐私与版权

- 网站保持仅本人可访问。
- API 密钥只存服务器，不进入 GitHub。
- 原文件和提取文本不得发送到未启用的第三方服务。
- 记录每个 AI 任务实际调用的服务商。
- 个人学习整理不自动等同于拥有公开传播权；不得把受版权保护的全文改成公开网站。
- 资源档案必须保留来源和出版信息。
- 外部链接失效不自动删除历史档案，只标记需要检查。

## 10. 推荐开发阶段

### 第二版 A：PDF 最小可用版

- 新增“资源整理”导航和工作台
- 支持文字版 PDF 上传
- 提取文字并按文章生成候选
- 调用 DeepSeek 输出结构化 JSON
- 提供审核、合并、拆分和编辑
- 确认后进入资源库
- 可选择删除原 PDF

暂不包含：扫描件 OCR、自动下载期刊、批量 GitHub 抓取。

### 第二版 B：阅读与检索增强

- 清洁阅读页
- 全文搜索
- 阅读进度、收藏和笔记
- 生词与重点表达
- Markdown/JSON 导出

### 第三版：视频整理

- 视频链接与字幕归档
- DeepSeek 生成章节、摘要和关键词
- 时间点跳转
- 观看进度和笔记
- 无字幕视频转写接口

### 第四版：自动化来源

- 白名单 RSS/API/GitHub 来源
- 定时检查新内容
- 去重、待审核队列和失败重试
- 用量与费用看板

## 11. 第一阶段验收标准

使用一份带文字层的英文杂志 PDF 验收：

1. 能识别文件页数并提取可搜索英文文本。
2. 能建立刊物、日期和文章序号的父子结构。
3. 每篇文章至少有标题、页码、主题、关键词、中文摘要和英文正文。
4. 用户可合并、拆分和修改 AI 结果。
5. 未经确认的结果不会进入正式资源库。
6. 确认后的文章可在手机和平板阅读并能全文搜索。
7. 可选择删除原 PDF，删除前有提示，整理结果仍保留。
8. DeepSeek 密钥不出现在网页源代码、GitHub 或备份文件中。
9. 每次处理可查看调用量、费用和失败原因。
10. 同一文件重复上传时能够提示并阻止重复归档。

## 12. 默认决策与后续确认项

为便于直接开发，建议默认采用：

- DeepSeek 负责网站自动文本整理。
- ChatGPT/Codex 负责网站维护和疑难复核，不作为网站自动 API。
- PDF 先支持文字版，扫描件 OCR 后做。
- 视频先支持链接和字幕，暂不长期保存视频文件。
- 所有 AI 结果先审核再归档。
- 原 PDF 在确认归档后由用户选择保留或删除。
- 自动来源必须加入白名单，并确认许可证或使用权限。

正式开发前仍需确认：

1. 首个测试 PDF 的实际版式与大小。
2. 每篇文章是否需要中英双语标题和英文摘要。
3. 原 PDF 默认保留、保留 7 天，还是确认后立即删除。
4. DeepSeek 每月预算上限。
5. 是否需要扫描件 OCR，以及预计扫描件占比。
6. 视频主要来源平台及是否通常带字幕。

## 13. 当前技术依据

- [DeepSeek JSON Output 官方说明](https://api-docs.deepseek.com/guides/json_mode/)：可要求模型返回可解析 JSON，适合文章元数据自动入库。
- [DeepSeek Chat Completion 官方接口](https://api-docs.deepseek.com/api/create-chat-completion)：网站通过服务端文本接口调用，密钥不能放在浏览器中。
- [DeepSeek 模型与价格](https://api-docs.deepseek.com/quick_start/pricing/)：模型和价格可能调整，网站应做成可配置项。
- [OpenAI：ChatGPT 订阅与 API 分开计费](https://help.openai.com/en/articles/8156019-is-api-usage-included-in-chatgpt-subscriptions-even-if-i-have-a-paid-chatgpt-account)：ChatGPT 会员不能直接作为网站 API 额度。
